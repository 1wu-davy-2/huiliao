# “会聊”产品计划书

> 文档状态：MVP 基线方案  
> 更新日期：2026-08-06  
> 产品形态：响应式单页网页应用  
> 目标市场：中国大陆中文用户  
> 准入范围：18 岁以上成年人

## 1. 项目摘要

“会聊”是一款面向缺少约会沟通经验、在异性交流中容易紧张或回避的成年男性的互动训练产品。它通过分支情境、消息诊断、即时反馈和低风险练习，帮助用户学习自然开启交流、延续话题、表达好感、提出邀约、接受拒绝，以及在亲密互动中确认双方意愿。

产品不提供用于欺骗、操控、施压、纠缠或绕过拒绝的“必胜话术”，不把女性当作可以通过技巧攻克的对象，也不以回复率、约会率或发生身体关系作为成功标准。产品训练的是用户可控制的沟通行为，而不是对方必须给出的结果。

## 2. 背景与机会

部分成年男性在成长过程中缺少与异性平等交往的机会，进入大学或职场后会遇到以下困难：

- 想认识对方，却不知道如何自然开口。
- 聊天容易变成连续提问，缺少自我表达和情绪回应。
- 害怕表达好感，或一次投入过多、给对方造成压力。
- 把回复速度和拒绝理解为个人价值评价。
- 不会发出具体、低压力且容易拒绝的邀请。
- 无法区分积极回应、信息不足、迟疑和拒绝。
- 对成年人亲密互动中的清醒、自主、明确、具体和持续同意缺少实践认知。

市面上大量内容给出脱离语境的“金句”，甚至强化性别刻板印象。真正的产品机会是提供一个可重复、低风险、能解释原因的练习环境，让用户形成判断力，而不是依赖复制台词。

## 3. 产品定位

### 3.1 一句话定位

面向缺少约会经验的成年男性，提供尊重、真诚、有边界的关系沟通练习。

### 3.2 品牌策略

- 公开名称：会聊
- 副标题：成年人的关系沟通练习场
- 品牌气质：平静、直接、成人化、务实，不说教也不油滑
- 不使用的公开语言：拿下、征服、攻克、服从测试、雌竞、段位、成功率

原始创意中的刺激性命名会吸引错误用户，并让真正缺少经验的用户误以为产品只提供套路，因此不进入公开界面、SEO 文案和应用内指标。

## 4. 目标与非目标

### 4.1 产品目标

1. 让用户能在三分钟内进入一个与当前困境相关的练习。
2. 让用户理解一句表达为何合适，而不是只获得可复制台词。
3. 训练清晰表达、倾听回应、分寸、边界和拒绝处理五项能力。
4. 帮助用户把“必须获得对方认可”转化为“完成一次尊重且真实的表达”。
5. 对高风险意图进行明确拦截，并给出合乎边界的替代行动。

### 4.2 非目标

- 不承诺提升回复率、脱单率、约会率或性关系转化率。
- 不教授虚构身份、隐瞒关系状态、打压、嫉妒诱导、忽冷忽热或虚假承诺。
- 不帮助用户绕过拒绝、跨平台纠缠、跟踪、灌酒或利用脆弱状态。
- 不处理未成年人相关的约会或亲密内容。
- 不提供实时自动代聊、批量搭讪、社交账号抓取、定位或联系人导入。
- MVP 不建设公开社区，不引入内容审核成本不可控的用户广场。
- 不替代心理治疗、法律建议、婚恋咨询或危机干预。

## 5. 目标用户

### 5.1 核心用户

- 18 岁以上。
- 初入大学高年级、研究生阶段或职场，异性社交经验较少。
- 生活圈较窄，在线下或聊天软件中容易紧张。
- 希望建立真实的约会或伴侣关系，愿意尊重对方的选择。
- 需要具体练习、反馈和可执行的小任务，而不是抽象理论。

### 5.2 典型画像

**画像 A：不知道怎么开始**  
23 岁，刚工作。在线下有正常社交，但遇到喜欢的人会过度思考第一句话，最后长期不行动。

**画像 B：会开口但聊不下去**  
26 岁，聊天常变成“在吗、吃了吗、做什么工作”的连续提问。对方回复变短后会焦虑并继续追问。

**画像 C：不敢表达或不会退出**  
29 岁，害怕被拒绝，长期用朋友身份隐藏好感；一旦表达后又容易反复追问原因，不知道如何体面收尾。

### 5.3 排除用户

以下意图不属于产品服务范围：控制、报复、骚扰、欺骗、偷拍、灌酒、利用职权或经济依赖、无视拒绝，以及涉及未成年人或无法自主同意者的亲密行为。

## 6. 用户任务

| 用户处境 | 用户真正需要完成的任务 | 产品提供的帮助 |
| --- | --- | --- |
| 不知道第一句说什么 | 依据共同情境自然开启一次交流 | 情境拆解、三种表达结构、低风险练习 |
| 聊天像面试 | 在提问、自我分享和情绪回应之间取得平衡 | 对话分支、比例提示、回复反馈 |
| 想表达好感 | 清晰说明兴趣，同时不给对方压力 | 表达模板结构、不同回应的下一步 |
| 想邀请见面 | 给出具体安排，并为拒绝留下容易的出口 | 邀约构成检查、模拟回应 |
| 对方变冷淡 | 判断继续、换话题还是结束 | 信号分级、停止条件、情绪复盘 |
| 被拒绝 | 接受结果、停止推进并保护自尊 | 退出练习、认知复盘、现实小任务 |
| 进入亲密互动 | 询问并持续确认双方意愿 | 同意检查、迟疑识别、暂停练习 |

## 7. 产品原则

1. **真实优先于技巧**：建议必须能让用户用自己的语言重写。
2. **语境优先于金句**：没有上下文时，不假装存在万能回复。
3. **行为优先于结果**：只评价用户可控制的表达和行动。
4. **双方都是主体**：不概括“女生都喜欢什么”，只分析具体行为和回应。
5. **不确定就放慢**：沉默、迟疑、被动顺从和过去的同意都不是当前同意。
6. **拒绝不需要破解**：收到拒绝后，正确动作是接受和停止推进。
7. **隐私默认最小化**：不要求姓名、照片、联系方式或完整聊天记录。

## 8. MVP 范围

### 8.1 P0：首版必须完成

| 模块 | 能力 |
| --- | --- |
| 成年确认与首次设置 | 18+ 确认、选择当前困难、简短基线自测、确认互动原则 |
| 训练首页 | 今日推荐、能力概况、继续练习、快捷进入常见困境 |
| 情境库 | 按关系阶段、渠道、目的和互动状态筛选 |
| 分支模拟对话 | 选择或输入回应、查看对方反应、即时解释、允许重试 |
| 消息实验室 | 对用户草稿进行清晰度、压力感、倾听和边界诊断，给出改写原因 |
| 边界专项 | 拒绝、不回复、醉酒、迟疑、权力差和反复联系情境训练 |
| 进度与复盘 | 记录已完成场景、能力变化、收藏和私密笔记 |
| 隐私控制 | 本地保存说明、导出数据、一键清除 |
| 安全拦截 | 对操控、欺骗、强迫、灌酒、纠缠、偷拍、未成年人等意图拒绝提供执行建议 |

### 8.2 P1：验证 MVP 后考虑

- 个性化训练路径。
- 语音表达和语速练习。
- 经明确授权的云端同步。
- 更丰富的模拟角色、城市和生活场景。
- 匿名化的能力趋势统计。
- 由专业人士审核的专题内容。

### 8.3 暂不进入范围

- 公共发帖、评论和私信。
- 真人匹配或约会撮合。
- 自动读取微信、QQ 或其他社交平台消息。
- 代表用户自动发送消息。
- 付费情感导师市场。
- 任何“成功率排行榜”或女性评分系统。

## 10. 核心流程

### 10.1 首次使用

1. 确认已满 18 岁。
2. 选择最多两个当前困难，例如“不知道怎么开口”“害怕被拒绝”。
3. 完成三个简短基线判断题。
4. 阅读并确认三条互动原则：真诚表达、容易拒绝、拒绝后停止。
5. 进入针对当前困难的首个练习，不经过营销落地页。

### 10.2 情境练习

1. 用户选择关系阶段、场景和目标。
2. 系统交代必要背景和对方上一条表达。
3. 用户从三种回应中选择，或输入自己的版本。
4. 系统展示对方可能的回应，不承诺单一真实结果。
5. 系统从五个维度给出反馈，并解释对方可能感受。
6. 用户查看一个更合适的表达结构后重试。
7. 通过边界检查后完成练习，并获得一个低压力现实任务。

### 10.3 消息实验室

1. 提示用户先删除姓名、电话、账号、地址等信息。
2. 用户选择关系阶段、自己真实意图并粘贴少量上下文。
3. 系统先做安全与边界检查。
4. 合规内容进入诊断，输出优点、风险、修改原因和三种自然版本。
5. 用户必须用自己的语言完成一次重写，避免形成代聊依赖。

### 10.4 拒绝或无回复

1. 系统识别明确拒绝、婉拒、连续不回应或要求停止联系。
2. 建议只允许“简短接受”和“停止联系”，不提供追问或换平台策略。
3. 用户完成情绪命名和一次复盘。
4. 现实任务围绕自我调节和正常生活，不围绕重新接触对方。

### 10.5 亲密沟通

1. 先确认双方均为成年人，且清醒、自由、无明显权力压力。
2. 训练直接但不施压的询问，例如“我想吻你，可以吗？”
3. 对“好像没有拒绝”“喝多了但很主动”“之前同意过”等判断给出纠正。
4. 任一方迟疑、沉默、僵住、改变主意或无法清晰表达时，正确动作都是暂停。
5. 强调同意只针对当前、具体行为，可随时撤回。

## 11. 功能规格

### 11.1 成年确认与首次设置

- 未确认 18+ 时不能进入亲密关系相关内容。
- 选择困难后立即生成推荐练习顺序。
- 首次设置控制在 90 秒内，可返回修改。
- 不收集真实姓名、性别证明、联系方式或精确位置。

### 11.2 训练首页

- 顶部显示当前训练目标和连续练习状态，但不制造“断签惩罚”。
- 主操作是“继续练习”，同时提供“我现在卡在……”的快速入口。
- 能力概况展示五项能力，不展示约会或性结果数字。
- 最近复盘仅展示用户主动保存的内容。

### 11.3 情境库

筛选维度：

- 关系阶段：陌生人、熟人、朋友、刚匹配、持续聊天、初次约会、稳定交往。
- 沟通渠道：线下、即时消息、语音、约会现场。
- 目的：认识、续聊、表达好感、邀约、澄清关系、处理冲突、结束互动、亲密沟通。
- 互动状态：积极回应、信息不足、回复冷淡、明确拒绝。

每个情境卡必须显示预计时长、难度、训练能力和边界标签。

### 11.4 分支模拟对话

- 每个场景至少包含三个决策节点和两个不同结局。
- 模拟对象可能积极、普通、迟疑、拒绝或结束交流，避免始终奖励用户。
- 每次选择后反馈必须解释原因，而不是只显示分数。
- 不合适选项可以出现用于教学，但不能以刺激、羞辱或“坏男人”作为奖励。
- 支持重新选择和回看关键节点。

### 11.5 沟通反馈模型

每条回应使用五个维度，每项 0–100：

| 维度 | 判断重点 |
| --- | --- |
| 清晰 | 是否表达了真实目的，句子是否容易理解 |
| 真诚 | 是否符合上下文，是否避免伪装、夸大和套路 |
| 倾听 | 是否回应了对方实际表达，而非只顾自己的目标 |
| 分寸 | 是否控制消息密度、索取程度和情绪负担 |
| 边界 | 是否允许对方轻松拒绝，并在迟疑或拒绝后停止 |

反馈固定结构：做得好的地方 → 可能造成的感受 → 一个关键修改 → 示例结构 → 用户自行重写。

### 11.6 消息实验室

- 输入上限 600 个中文字符，默认不保存原文。
- 提供关系阶段、沟通目的和对方回应状态三个必要选择。
- 诊断结果最多给三个版本：直接、轻松、稳重。
- 每个版本必须附“为什么这样改”和“何时不该继续”。
- 检测到高风险意图时，不输出可执行细节，只显示边界说明和安全替代行动。

### 11.7 进度与复盘

- 记录完成场景、重试次数、五维能力趋势和边界判断正确率。
- 复盘问题：我表达了什么、对方实际表达了什么、我尊重了什么边界、下次只改哪一点。
- 不记录“拿到联系方式数”“成功邀约数”或“发生关系数”。
- 用户可导出 JSON，并一键清除全部本地数据。

统一内容模板：

```text
情境背景
→ 用户可控制的合理目标
→ 推荐原则
→ 三种回应及潜在感受
→ 对方不同回应的下一步
→ 不推荐做法
→ 同意/边界检查
→ 复盘问题
```

## 13. 安全与同意规则

### 13.1 必须拦截的意图

- 欺骗身份、收入、关系状态或真实目的。
- 打压、羞辱、冷暴力、制造嫉妒或情绪依赖。
- 强迫、威胁、灌酒、下药、堵门、偷拍视频。
- 反复联系、换账号、跨平台追踪或找朋友施压。
- 利用未成年人、醉酒、疾病、经济依赖或明显权力差。
- 把沉默、穿着、约会次数、进入私人空间或过去的同意当作当前同意。

### 13.2 拦截响应结构

1. 简短说明不能帮助执行该意图。
2. 指出具体风险，不给危险做法补充细节。
3. 给出一个安全替代，例如停止联系、直接澄清、等待清醒后再询问。
4. 必要时建议离开现场或寻求可信赖的现实支持。

### 13.3 同意判断

同意必须同时满足：

- 双方均为成年人。
- 清醒且能理解当前行为。
- 没有威胁、职权、经济或环境压力。
- 对当前具体行为给出明确意愿。
- 在过程中持续存在，并可随时撤回。

任何一项不确定，都不继续推进。

涉及进一步性行为时，产品只提供“事前沟通哪些问题”的教育性提示，包括避孕安排、性健康、隐私期待、舒适程度和随时暂停；不提供医疗诊断或具体性行为技巧。相关正式内容在公开发布前需由具备资质的健康专业人士审核。

## 14. 视觉与交互方向

### 14.1 总体风格

- 工作台式、安静、可信，避免恋爱营销页和夸张“成功学”视觉。
- 第一屏直接进入训练，不做大型宣传 Hero。
- 使用暖白、深墨色为基础，青绿色为主操作色，珊瑚色用于风险提醒，金色用于进度强调；避免单一蓝紫或大面积渐变。
- 卡片圆角不超过 8px，边框清晰，阴影克制。
- 标题在紧凑面板内保持中等字号，不使用占满屏幕的展示字体。

### 14.2 页面结构

- 桌面端：232px 左侧导航 + 弹性主内容区，主内容最大宽度约 1180px。
- 移动端：顶部上下文栏 + 64px 底部导航，主要操作放在拇指可达区。
- 对话练习区保持稳定高度，回复、加载或反馈出现时不推动整页剧烈跳动。
- 图标使用统一图标库，陌生图标提供 tooltip。

### 14.3 视觉资产

- 使用本地 WebP 资产，展示成年人的真实沟通场景，如咖啡店、兴趣活动、散步和日常聊天。
- 人物形象应自然、多样，不做性暗示，不使用刻板“高价值男性”形象。
- 模拟角色使用一致风格的成人头像，并明确其为虚构练习角色。
- 不依赖远程图片热链；所有资产记录来源或生成说明。

### 14.4 可访问性

- 文本与背景达到 WCAG AA 对比度。
- 所有核心流程支持键盘操作，焦点状态可见。
- 表单使用明确标签，错误信息与输入关联。
- 支持 `prefers-reduced-motion`。
- 在 360px 宽度下无横向滚动、遮挡或文字溢出。

## 15. 数据与隐私

### 15.1 MVP 数据策略

- 默认只在浏览器本地保存设置、进度、收藏和用户主动保存的复盘。
- 消息实验室原始输入完成诊断后不持久化。
- 不接入第三方广告、用户画像或跨站跟踪。
- 不要求注册即可完成全部 MVP 训练。

### 15.2 用户控制

- 清楚展示保存了哪些数据。
- 支持导出结构化 JSON。
- 支持一键清除，操作前二次确认。
- 删除后刷新页面不能恢复旧数据。

### 15.3 未来接入在线服务时

必须另行完成隐私、内容安全、数据保留和当地合规评审；任何模型密钥不得放在前端，真实聊天文本必须遵循最小化上传和可删除原则。

## 16. 成功指标

### 16.1 北极星指标

每周完成一个情境、根据反馈重试，并通过边界检查的有效练习用户数。

### 16.2 MVP 指标

- 首次访问完成首个练习的比例。
- 首周完成至少三个不同情境的比例。
- 同类场景重试后的五维能力变化。
- 正确识别拒绝、迟疑和无法同意场景的比例。
- 两周后用户自评沟通焦虑与回避程度的变化。
- 用户自愿记录一次尊重、清晰的现实沟通行为的比例。
- 高风险请求拦截测试的召回率和误放率。

### 16.3 禁止指标

不把回复数量、获得联系方式、成功邀约、恋爱关系或身体关系数量作为产品增长和用户能力指标。

## 17. 风险与缓解

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 品牌吸引操控型用户 | 产品内容被滥用 | 中性定位、明确非目标、入口意图提示 |
| 建议被当成万能台词 | 用户机械复制并形成依赖 | 强制解释原因、提供结构、要求自行重写 |
| 用户输入真实隐私 | 泄露本人或第三方信息 | 脱敏提示、默认不保存、输入长度限制、一键清除 |
| 模糊信号被误读 | 造成越界或伤害 | 不确定统一按放慢、询问或停止处理 |
| 强化性别刻板印象 | 伤害双方并降低可信度 | 只评价具体行为，不推断群体心理，内容多元评审 |
| 用户因拒绝产生敌意 | 纠缠或自我伤害风险 | 不羞辱反馈、拒绝专项、自我调节和现实支持提示 |
| 前端规则被绕过 | 危险建议漏出 | 固定安全评测集；在线服务上线前增加服务端策略层 |

## 18. 里程碑

### 阶段 0：产品与内容基线

- 确认定位、术语、首批 12 个场景和安全规则。
- 完成页面结构与核心数据模型。
- 交付编码任务书。

### 阶段 1：可用前端 MVP

- 实现全部 P0 页面和本地数据。
- 至少完成 8 个可玩的分支场景，其中包含 3 个拒绝/同意场景。
- 完成响应式、键盘操作和自动化测试。

### 阶段 2：小范围验证

- 邀请目标用户完成任务测试。
- 验证首次练习完成率、内容理解和边界判断正确率。
- 修正文案、分支和误判，不采集现实亲密结果。

### 阶段 3：在线能力评估

- 只有在隐私和安全方案通过评审后，才评估后端账户、同步或生成式建议。

## 19. MVP 完成定义

当且仅当满足以下条件，MVP 才视为完成：

- 用户在手机端三步内进入一个具体练习。
- 首次设置、首页、情境库、模拟对话、消息实验室、进度和设置均可完整使用。
- 至少 8 个分支场景有真实分支、解释、重试和复盘，不是静态展示。
- 操控、强迫、灌酒、纠缠、偷拍、未成年人和权力差测试用例均被拦截。
- 所有亲密情境都体现清醒、自主、明确、具体、持续且可撤回的同意。
- 本地数据可导出并彻底清除，消息原文默认不持久化。
- 360px、768px 和 1440px 视口无横向滚动、内容遮挡或按钮失效。
- 自动化测试、生产构建和核心无障碍检查通过。

## 20. 已确定的产品决策

- 服务成年男性，但内容不对女性进行群体化推断。
- 公开产品名使用“会聊”，不使用刺激性原始创意名。
- 首版是可完整操作的前端 MVP，不引入登录、后端和外部生成服务。
- 亲密关系内容保留，但只训练双方意愿表达、同意确认、暂停和退出。
- 进度只评价沟通能力和边界判断，不评价用户获得的关系结果。
