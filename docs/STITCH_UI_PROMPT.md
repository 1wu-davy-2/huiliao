# 会聊 UI 生成话术（Stitch）

把下面整段作为 Stitch 的产品 UI 生成提示词使用。首页视觉可以自由探索，但必须保留现有业务信息和安全边界。

## 主提示词

你正在为一个已经可以使用的中文 Web 应用重新设计 UI，不要生成营销落地页。产品名称是“会聊”，副标题是“成年人的关系沟通练习场”。目标用户是 18 岁以上、希望练习尊重沟通的成年人。产品只评价用户能控制的表达与行为，不承诺恋爱结果；收到拒绝、迟疑或停止信号后应停止推进。

请设计一个高完成度、具有强品牌识别度、酷而有吸引力的训练工作台。它应该像一个有内容、有状态、有反馈的数字训练工具，而不是普通 SaaS 卡片堆叠，也不是游戏化地“通关对方”。允许大胆探索字体、网格、边界线、局部高对比色、编辑器式布局和轻量动效，但要保持中文长文本可读、按钮可操作、移动端不拥挤。

不要使用：大面积渐变、紫色渐变、发光球体、漂浮玻璃卡片、装饰性 3D、营销 Hero、过多圆角卡片嵌套、夸大“成功率”、恋爱结果排行榜、操控或“拿下对方”的文案。页面必须像真实产品，首屏直接进入训练工作台。

品牌标志使用一个简洁的聊天气泡图形，不在小尺寸图标里放中文字符；浏览器 favicon 也使用同一图形。请为桌面端 1440×900 和移动端 390×844 同时设计，提供清晰的响应式折叠规则。

## 页面 1：训练工作台首页

页面标题：`今天练哪一场？`

辅助文案：`下一步不是取悦对方，而是把话说清楚。`

首屏包括：

- 今日推荐训练，显示标题、预计时长、难度、训练能力和“继续训练”按钮。
- 五个“我现在卡在……”快捷入口：`不知道怎么开口`、`对方回复变短`、`想发出邀约`、`刚被拒绝`、`不确定边界`。
- 能力概况：清晰、真诚、倾听、分寸、边界；只显示训练反馈，不显示恋爱结果。
- 最近复盘：显示最近一条本地复盘，没有数据时显示空状态。
- 明确但不抢眼的本地数据提示：设置、进度、收藏和复盘保存在当前浏览器。

## 页面 2：实验室入口

保留现有一级导航 `首页 / 练习 / 实验室 / 进度 / 设置`。实验室页面顶部提供两个清楚的入口：

- `消息诊断`：粘贴消息草稿，进行本地规则诊断。
- `AI 试炼场`：使用用户自己的模型连接，进行可重复的随机挑战。

不要新增第六个移动底部导航项；AI 试炼场属于实验室内部的二级入口。

## 页面 3：AI 试炼场设置

页面标题：`AI 试炼场`

顶部模式切换：`沟通试炼` / `Prompt 工程试炼`

难度切换：`简单` / `一般` / `困难`

设置区字段：

- `协议`：OpenAI-compatible / Anthropic / Gemini
- `连接目标`：`官方预设` / `自定义地址`
- 选择官方预设时只读显示服务域名，不允许直接编辑；选择自定义地址后再显示 `Base URL`，允许填写自己的公网 HTTPS 代理或兼容网关
- `模型 ID`
- `API Key`：密码输入框，旁边显示 `只在本次页面内存中使用，不会保存；浏览器扩展、开发者工具和中转服务仍可能看到它`
- `最大轮数`：5–30 的滑杆或数字步进器
- `随机换一题` 按钮
- `测试连接` 按钮
- 首次请求前的确认：`我知道输入和模型回复会发送到我填写的模型服务`
- 费用提示：`结束后的模型自评会额外调用一次当前模型，并消耗 Token 或账户余额`

切换协议、官方预设或自定义目标主机时，界面应立刻清空旧 API Key 和确认勾选，并要求用户确认新的目标域名。不要让同一份密钥在目标地址变化后继续保留。

挑战预览要显示：挑战标题、任务目标、预计轮数、验收条件摘要和“开始试炼”。一次试炼只随机选一道题，后续 5–30 轮都围绕这道题进行。不要把配置字段做成拥挤的长表单；桌面端可以采用左右分区，移动端改为纵向步骤。

## 页面 4：沟通试炼进行中

页面结构：

- 左侧或顶部：挑战 brief、难度、当前轮数，例如 `第 3 / 12 轮`。
- 中央：对话区，区分“对方”和“我”，显示正在生成、请求失败、取消请求等状态。
- 底部：多行输入框、发送按钮、`结束并评估` 按钮。
- 侧边或抽屉：当前安全提醒和可验证指标，不显示操控技巧。

界面文案：

- `这是一场可复盘的模拟，不预测真实关系结果`
- `对方可以拒绝，你也可以随时结束`
- `模型回复生成中`
- `本轮失败，未消耗轮数`
- `已达到你设定的轮数`

## 页面 5：Prompt 工程试炼进行中

页面结构：

- 挑战说明与固定测试输入。
- 用户 Prompt 编辑器，支持清空、复制、提交新版本。
- 模型输出区，显示纯文本或结构化 JSON 的格式状态。
- 右侧/下方“硬规则检查”：非空、JSON、必含项、长度和安全边界。
- 显示 `第 2 / 8 次提交`，每次提交占用一轮。

不要把 Prompt 工程做成无限聊天窗口；它是“写一版、运行一次、看结果、再改一版”的实验流程。

## 页面 6：结果与本地历史

结果页分成两个明确区域：

- `硬规则检查`：程序验证的通过/未通过列表和具体原因。
- `模型自评`：分数、做得好的地方、可改进点、下一步建议。

固定免责声明：`模型自评，仅供比较，不是客观基准。`

在自评标题旁再次显示短提示：`本次自评额外调用了 1 次模型。`

本地历史页面显示：挑战、模式、难度、模型名称、使用轮数、完成时间和硬规则分数。提示：`完整对话只保存在当前浏览器 IndexedDB，最近 20 次或 25 MB，达到上限自动清理最旧记录。`

提供 `查看对话`、`导出本次`、`删除本次`、`清除全部试炼记录`。API Key 永远不出现在历史记录中。

## 交付要求

请输出：

1. 桌面端首页、实验室入口、AI 设置、沟通试炼、Prompt 工程试炼、结果页。
2. 移动端对应的折叠布局，不出现横向滚动，不让底部导航遮住输入框或结束按钮。
3. 空状态、加载、失败、达到轮数上限、无历史记录、历史已满自动清理等状态。
4. 统一的 favicon/品牌标记方向，图形在 16 px 下仍清楚。
5. 所有按钮、输入框、滑杆、分段控件和标签都给出中文可访问名称。

请优先给出真实可实现的组件层级和间距，而不是只给一张无法拆解的海报式图片。
