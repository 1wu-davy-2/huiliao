# 不依赖 Playwright 的 MVP 测试与验收方案

> 适用状态：Playwright 因浏览器运行文件下载或环境配置问题无法继续时。  
> 目标：不阻塞项目交付，同时保留诚实、可重复的质量结论。  
> 本方案不删除现有 `tests/e2e` 和 `playwright.config.ts`，只将浏览器自动化标记为暂缓。

## 1. 当前处理决定

可以停止继续安装或调试 Playwright 浏览器。现有 E2E 文件保留，后续环境允许时可以恢复使用，不需要为了本轮验收删除或重写。

本轮质量状态使用以下四种结果：

- `PASS`：命令或检查实际执行并通过。
- `FAIL`：实际执行后发现问题。
- `BLOCKED`：受环境限制无法执行，例如缺少 Playwright 浏览器。
- `NOT RUN`：尚未执行，不能写成通过。

Playwright 应记录为 `BLOCKED（环境：缺少可用浏览器运行文件）`。README 和交付报告不得把它写成“E2E 已通过”或“全量验证已通过”。

## 2. 推荐验收组合

本轮使用以下组合替代 Playwright：

```text
ESLint 静态检查
    ↓
Vitest 单元与 jsdom 组件测试
    ↓
TypeScript + Vite 生产构建
    ↓
本地 Preview HTTP 冒烟检查
    ↓
本机 Edge/Chrome 人工关键路径检查
    ↓
三视口布局、键盘、内容和边界专项验收
```

前四项可以发现代码、类型、数据结构和基础集成问题；最后两项负责真实浏览器渲染、交互、响应式和可访问性。两部分缺一不可。

## 3. 自动检查

在项目根目录依次执行，任一命令失败都先记录失败原因，不要跳过后声称通过。

### 3.1 ESLint

```powershell
npm run lint
```

通过标准：

- 退出码为 `0`。
- 没有 error。
- warning 需要记录；与 React Hooks、未使用状态或无障碍相关的 warning 应在发布前处理。

### 3.2 Vitest

```powershell
npm run test
```

现有测试应至少覆盖：

- 成年确认、首次设置步骤和最多选择两个困难。
- 消息诊断的 `ok`、`caution`、`blocked`。
- 操控、强迫、灌酒、纠缠、偷拍、未成年人和权力差安全规则。
- 场景 Zod schema、节点引用、可达性、可结束性、无环和危险选项说明。
- 五维能力计算与推荐逻辑。
- 本地存储读取、迁移、导出、清除、收藏和复盘。
- 情境库筛选和空状态。

通过标准：

- 退出码为 `0`。
- 失败数为 `0`。
- 记录实际测试文件数和用例数，不直接照抄 README 中的旧数字。

### 3.3 生产构建

```powershell
npm run build
```

通过标准：

- TypeScript 项目引用构建成功。
- Vite 生产构建成功。
- `dist` 中存在 `index.html` 和打包后的 JS/CSS 资产。
- 构建日志没有类型错误或资源解析错误。

### 3.4 构建产物检查

```powershell
Get-ChildItem -Recurse -File dist | Select-Object FullName,Length
```

检查：

- `dist/index.html` 存在且不是空文件。
- JS 和 CSS 文件大小大于 `0`。
- 不应包含 `.env`、源聊天草稿、测试报告或开发机绝对路径。

可使用以下命令做简单敏感信息扫描：

```powershell
rg -n -i "api[_-]?key|secret|password|bearer |localhost:[0-9]+" dist
```

没有匹配时 `rg` 返回非零状态是正常现象，不代表构建失败。

## 4. HTTP 冒烟检查

先在一个 PowerShell 窗口启动生产预览：

```powershell
npm run preview -- --host 127.0.0.1 --port 4173
```

保持该窗口运行，在第二个 PowerShell 窗口执行：

```powershell
$routes = @(
  '/',
  '/onboarding',
  '/practice',
  '/practice/s02',
  '/lab',
  '/progress',
  '/settings'
)

foreach ($route in $routes) {
  $url = "http://127.0.0.1:4173$route"
  $response = Invoke-WebRequest -UseBasicParsing -Uri $url
  [pscustomobject]@{
    Route = $route
    Status = $response.StatusCode
    HasRoot = $response.Content -match 'id="root"'
  }
}
```

通过标准：

- 全部路由返回 `200`。
- 全部响应包含 React 根节点 `id="root"`。
- 深层路由 `/practice/s02` 可以直接访问，不返回服务器 404。

这一步只验证静态服务和 SPA 回退，不代表页面 JavaScript 已正确运行。

## 5. 用 Vitest 替代关键 E2E 的方案

Playwright 暂缓后，应优先把以下流程补成 React Testing Library + `MemoryRouter` 的组件集成测试。这些测试运行在 jsdom，不需要下载浏览器。

建议新增的测试文件及范围：

| 测试文件 | 覆盖内容 |
| --- | --- |
| `tests/unit/app-routing.test.tsx` | 未完成设置时跳转、未知路由、完成设置后打开各页面 |
| `tests/unit/scenario-page.test.tsx` | 三节点推进、重试、结局、完成记录、保存复盘 |
| `tests/unit/scenario-free-input.test.tsx` | 正常、谨慎、拦截自由输入；输入不得持久化 |
| `tests/unit/lab-page.test.tsx` | 三类诊断、自行重写、刷新状态、拒绝后不再给推进示例 |
| `tests/unit/progress-page.test.tsx` | 无记录、完成记录、边界判断、收藏和删除复盘 |
| `tests/unit/settings-page.test.tsx` | 导出内容、清除确认、重新首次设置 |

必须增加的边界回归用例：

1. `responseStatus = rejection` 时，无论 `purpose` 是邀约还是亲密沟通，都不能再输出推进关系的示例。
2. 对方迟疑、沉默、说“慢一点”或撤回同意后，下一步不能继续升级肢体接触。
3. 场景自由输入采用推荐表达时，只计一次当前节点回应，且进入下一节点后清空旧输入。
4. 普通表达“我们都是学生”不能被误判为师生权力差。
5. 未满 18 岁的多种说法必须被拦截，不只识别“未成年人”和“高中生”。
6. 教育性提问不能绕过同一条文本中的强迫、偷拍或灌酒意图。

这些用例是现有测试体系的补充，不需要 Playwright。

## 6. 人工浏览器验收

使用本机已经安装的 Edge 或 Chrome 打开 `http://127.0.0.1:4173`。先清除该站点的 `localStorage`，再按以下顺序操作。

### 6.1 首次设置

- 未勾选“已年满 18 岁”时不能继续，并显示可理解的错误。
- 当前困难最多选择两个。
- 三道基线题必须全部回答。
- 三条互动原则必须全部确认。
- 完成后进入首页；刷新后不再次进入首次设置。

### 6.2 首页与导航

- 首页不是营销页，主操作“继续练习”真实可用。
- 首页、练习、实验室、进度、设置五个入口均能打开。
- 浏览器前进、后退和刷新后页面状态合理。
- 没有练习记录时，不应把默认数值伪装成真实能力结果。

### 6.3 情境库

- 默认显示 8 个场景。
- 关系阶段、渠道、目的、互动状态可组合筛选。
- 无结果时有空状态，清除筛选后恢复。
- 收藏状态刷新后仍然存在。

### 6.4 模拟对话

- 至少完整走完 `s02`、`s07`、`s08`、`s10` 四个代表场景。
- 每个节点可选择、查看反馈、重试和继续。
- 对方可以冷淡、拒绝、迟疑或结束互动，不应始终给积极结果。
- 收到拒绝或撤回同意后，不再出现升级关系的合理选项。
- 自由输入的正常、谨慎和危险内容分别得到正确状态。
- 危险内容不展示执行性改写。
- 进入下一节点后旧输入清空，尝试次数没有重复增加。
- 结局能保存完成记录和可选复盘。

### 6.5 消息实验室

- 未选择完整上下文时不能诊断。
- 三个示例能够填入上下文和草稿。
- 正常内容出现三种表达及原因。
- 谨慎内容先显示压力或边界风险。
- 强迫、灌酒、纠缠、偷拍、未成年人等内容只显示拦截和安全替代。
- 当对方状态是“明确拒绝”时，不再显示邀约或亲密推进示例。
- 原始草稿和自行重写刷新后不会恢复。

### 6.6 进度与隐私

- 完成场景后首页和进度页同步更新。
- 收藏与复盘可以查看和删除。
- 导出的 JSON 可以打开，含 schema 版本和导出时间。
- 清除数据需要二次确认。
- 清除后刷新仍回到首次设置，旧进度不可恢复。

## 7. 三视口检查

使用浏览器开发者工具分别设置：

| 视口 | 重点 |
| --- | --- |
| `360 × 800` | 底部导航、筛选弹层、长按钮、软键盘附近提交区域 |
| `768 × 1024` | 64px 导航轨、内容宽度、弹层尺寸 |
| `1440 × 900` | 232px 侧栏、1180px 内容上限、筛选侧栏与对话高度 |

每个视口至少查看首页、情境库、`/practice/s02` 和消息实验室。

通过标准：

- 无横向滚动。
- 导航和主要按钮不遮挡内容。
- 最长中文标签不溢出。
- 对话区可以滚动，反馈出现时布局不会剧烈跳动。
- 图片和头像正常显示，无破图。
- 页面缩放到 200% 后核心操作仍可用。

建议人工保存截图到独立验收目录，但不要把截图当成功能测试的替代品。

## 8. 键盘与基础无障碍检查

不依赖自动工具也必须完成以下人工检查：

- 从地址栏开始只使用 `Tab`、`Shift+Tab`、`Enter`、空格和方向键完成首次设置。
- “跳到主要内容”链接获得焦点后可见且有效。
- 焦点顺序与视觉顺序一致，焦点轮廓清楚。
- 弹层打开后焦点留在弹层内；`Esc` 可以关闭；关闭后焦点回到触发按钮。
- 所有输入都有可见标签，错误信息能够被看见且不只依赖颜色。
- 图标按钮具有文字名称，例如收藏、关闭、删除。
- 开启系统“减少动态效果”后没有不必要动画。

人工检查不能替代完整 WCAG 审计，因此报告中应写“完成基础键盘检查”，不要写“无障碍完全合规”。

## 9. 内容与成年人边界验收

代码测试通过不等于内容通过。必须人工逐条检查 8 个场景、消息实验室示例和所有安全替代文案。

### 9.1 中文自然度

- 删除中英文混杂表达，例如正文中的 `judge`。
- 避免“人格展示”“信任清零”“必须立即服从”等生硬或歧义表达。
- 减少“她只能”“她一定会”等替对方断言感受的句式。
- 拒绝话术根据关系阶段调整，避免所有情境都使用过度正式的“我不会再联系你”。
- 示例应像真实中文聊天，但不能承诺结果或假装能预测对方反应。

### 9.2 同意与拒绝

- 所有人物明确为成年人。
- 同意必须清醒、自主、明确、针对当前具体行为、持续存在且可以撤回。
- 沉默、迟疑、僵住、被动顺从、饮酒受影响和过去的同意都不能代替当前确认。
- 对方说“不”“慢一点”“到这里就好”或要求停止后，流程立即停止推进。
- 拒绝适用于所有账号和平台，不提供换号、找朋友说情或反复联系方案。
- 不利用职权、经济依赖、醉酒、记忆模糊或其他无法自由拒绝的状态。

### 9.3 成年人亲密沟通覆盖

当前版本不能只停留在“牵手、亲吻”和“醉酒时停止”。若产品保留成年人亲密沟通模块，至少还要审查是否覆盖：

- 清醒双方如何直接表达进一步亲密意愿，并允许对方轻松拒绝。
- 行为发生前和过程中的持续确认、暂停与撤回。
- 避孕、性健康、隐私、舒适程度和事后沟通的事前讨论。
- 双方期待不一致时如何停止或改期。

只提供沟通和边界教育，不提供医疗诊断、露骨性行为教程或绕过同意的技巧。正式性健康内容上线前需要专业审核。

## 10. 本方案不能替代的内容

Vitest + jsdom 无法可靠发现：

- 真实浏览器中的 CSS 溢出、遮挡、字体和安全区域问题。
- 图片实际解码、资源 404 和生产环境控制台错误。
- 完整焦点行为、文件下载、浏览器历史和存储差异。
- 触屏、软键盘和不同设备的渲染问题。

因此，停止 Playwright 后，人工浏览器验收是发布前强制步骤，而不是可选步骤。若人工浏览器验收也未执行，项目只能标记为“代码检查通过，浏览器验收未完成”。

## 11. 最低发布门槛

以下项目全部满足，才可以标记为“无 Playwright 条件下通过 MVP 验收”：

- [ ] `npm run lint` 通过。
- [ ] `npm run test` 通过，并记录实际用例数。
- [ ] `npm run build` 通过。
- [ ] Preview 的 7 个路由 HTTP 冒烟检查通过。
- [ ] 本机浏览器完成首次设置、一个普通场景、一个拒绝场景、两个亲密边界场景和消息实验室三类结果。
- [ ] 360、768、1440 三视口无横向滚动或遮挡。
- [ ] 基础键盘与弹层焦点检查通过。
- [ ] 数据导出、清除和刷新验证通过。
- [ ] “明确拒绝后不输出推进示例”验证通过。
- [ ] 8 个场景及全部消息示例完成中文与同意边界审校。
- [ ] Playwright 如未执行，明确记录为 `BLOCKED`，不伪装成通过。

## 13. 后续恢复 Playwright

本轮无需继续处理。未来网络或环境稳定后，可选择以下任一方式恢复：

- 安装 Playwright 自带 Chromium 后运行现有 E2E。
- 配置 Playwright 使用机器上已有的 Microsoft Edge `channel: 'msedge'`，避免重复下载 Chromium。
- 在具备浏览器缓存的 CI 环境运行 E2E。

恢复后仍需重新执行并记录真实结果，不能沿用本轮人工验收结论。
