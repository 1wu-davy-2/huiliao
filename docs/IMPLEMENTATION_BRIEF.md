# “会聊”网页 MVP 编码任务书

## 任务目标

在当前空白仓库中实现一个可运行、可测试、视觉完成度高的响应式中文网页应用。“会聊”面向缺少约会沟通经验的成年男性，通过情境模拟、消息诊断、能力反馈和复盘，训练自然表达、倾听回应、低压力邀约、面对拒绝，以及成年人亲密互动中的明确和持续同意。

这不是营销落地页。用户打开后应直接进入成年确认或训练工作台，全部核心控件和页面必须真实可用。

完整产品依据见 [PRODUCT_PLAN.md](./PRODUCT_PLAN.md)。若两份文档存在理解差异，以本任务书的实现范围和验收标准为准。

## 1. 不可协商的边界

- 仅面向 18 岁以上成年人，首次进入必须确认年龄。
- 不承诺回复、邀约、恋爱或身体关系结果。
- 不提供操控、欺骗、打压、威胁、灌酒、偷拍、跟踪、反复联系或绕过拒绝的做法。
- 不处理涉及未成年人、明显醉酒或无法自主同意者的亲密建议。
- 不把沉默、迟疑、穿着、约会次数、进入私人空间或过去的同意视为当前同意。
- 收到拒绝、停止联系要求或连续不回应后，只能建议接受并停止推进。
- 亲密情境中的同意必须是清醒、自主、明确、针对当前行为、持续存在且可随时撤回。
- 不把女性概括为单一群体，不出现“女生都喜欢”“高价值男性”“拿下”等文案。

## 2. 技术方案

使用以下技术基线：

- Vite
- React
- TypeScript，开启严格模式
- React Router
- Zod，用于静态场景数据的运行时校验
- `lucide-react` 图标
- 原生 CSS 或 CSS Modules，使用 CSS 自定义属性管理设计令牌
- Vitest + React Testing Library
- Playwright + axe-core，用于关键流程、响应式和自动无障碍检查
- 浏览器 `localStorage`，通过独立 repository/adapter 封装

约束：

- 不接入后端、登录、数据库、支付或外部生成服务。
- 不在客户端出现 API key 或伪造网络请求。
- 不使用重量级 UI 组件库拼装默认样式。
- 所有内容数据与业务数据分离，场景放在 TypeScript/JSON 数据文件中。
- 为未来在线建议能力预留接口，但首版必须使用确定性本地规则完整运行。
- `npm run dev`、`npm run build`、`npm run test`、`npm run lint` 均需可执行。

建议目录结构：

```text
src/
  app/                 # 路由、布局、Provider
  components/          # 通用控件，不放业务规则
  features/
    onboarding/
    scenarios/
    message-lab/
    progress/
    settings/
  content/             # 场景、角色和示例数据
  schemas/             # Zod 数据契约
  lib/                 # safety、analysis、storage、export
  styles/              # tokens、global、responsive
tests/
  e2e/
public/
  images/
```

## 3. 路由与页面

| 路由 | 页面 | 必要功能 |
| --- | --- | --- |
| `/onboarding` | 首次设置 | 18+ 确认、困难选择、三题基线、互动原则 |
| `/` | 训练首页 | 今日练习、继续练习、能力概况、常见困境入口、最近复盘 |
| `/practice` | 情境库 | 多条件筛选、场景卡、空状态、清除筛选 |
| `/practice/:id` | 模拟对话 | 背景、稳定对话区、分支选择、自由输入、反馈、重试、复盘 |
| `/lab` | 消息实验室 | 脱敏提示、上下文选择、草稿输入、风险检查、诊断与自行重写 |
| `/progress` | 进度 | 五维能力、完成记录、边界正确率、收藏、私密复盘 |
| `/settings` | 设置 | 原则、数据说明、导出 JSON、清除数据、重新进行首次设置 |

未完成首次设置时，除首次设置页外的应用路由应重定向到 `/onboarding`。完成后再次打开应用应直接回到上次使用位置或首页。

## 4. 主导航与布局

一级导航固定为：首页、练习、实验室、进度、设置。

- 桌面端：232px 左侧导航，顶部显示当前页面上下文，主内容最大宽度 1180px。
- 平板端：可折叠窄侧栏或紧凑导航，不允许内容被遮挡。
- 移动端：顶部上下文栏，底部 64px 导航；底部导航必须考虑安全区域。
- 对话练习主体使用稳定尺寸，出现反馈、错误和加载状态时不能造成明显布局跳动。
- 页面不是卡片套卡片；分区使用留白、分隔线或全宽带，卡片只用于重复场景和真正独立的工具面板。

## 5. 视觉规范

### 5.1 品牌与色彩

公开展示：

- 产品名：会聊
- 副标题：成年人的关系沟通练习场

建议令牌，可在保证对比度的前提下微调：

```css
--bg: #f6f7f4;
--surface: #ffffff;
--ink: #202522;
--muted: #66706a;
--line: #d9dfda;
--primary: #217a70;
--primary-strong: #165e57;
--warning: #c45846;
--progress: #b78324;
--success: #2f7d4d;
```

- 不使用渐变、发光球、装饰性气泡或大面积蓝紫色。
- 卡片圆角最大 8px；按钮、输入框和工具栏保持紧凑。
- 字间距固定为 0，不通过视口宽度缩放字体。
- 正文优先系统中文字体栈，保证 Windows、macOS、Android 和 iOS 可读。
- 风险状态不能只依靠颜色，必须同时有图标和文本。

### 5.2 视觉资产

- `public/images` 中提供本地 WebP 图片或头像资产，不使用远程热链。
- 至少包含一张成年人日常交流主图和四个一致风格的虚构成人角色头像。
- 图片必须自然、克制、无性暗示；头像明确用于虚构练习角色。
- 记录资产来源或生成说明；有文字替代信息，装饰图使用空 `alt`。

### 5.3 图标与控件

- 使用 `lucide-react`，不手绘 SVG。
- 返回、收藏、重试、删除、导出等操作优先使用熟悉图标，陌生图标提供 tooltip。
- 单选场景使用 segmented control 或 radio group，多选困难使用 checkbox，布尔设置使用 switch。
- 所有图标按钮具有可访问名称，点击区域至少 44×44px。

## 6. 首次设置

实现四个紧凑步骤：

1. **成年确认**：勾选“我已年满 18 岁”，未勾选不能继续；同时说明产品不提供操控或绕过拒绝的做法。
2. **当前困难**：最多选择两个，“不知道如何开口”“聊天容易冷场”“不敢表达好感”“害怕被拒绝”“不确定如何把握边界”。
3. **基线判断**：三道单选题，覆盖连续追问、低压力邀约和迟疑时暂停。
4. **互动原则**：确认“真实表达”“让对方容易拒绝”“拒绝后停止”。

完成后写入本地设置，生成推荐场景，并跳转首页。提供进度指示、上一步和退出说明；移动端不出现文字或按钮溢出。

## 7. 首页

首页必须像训练工作台，不做大型 Hero。

必需内容：

- 问候与当前训练目标，标题不超过两行。
- 主按钮“继续练习”，进入推荐或上次未完成的场景。
- “我现在卡在……”快捷操作：不知道怎么开口、对方回复变短、想发出邀约、刚被拒绝、不确定边界。
- 五维能力概况：清晰、真诚、倾听、分寸、边界。
- 今日推荐场景，显示时长、难度和主要能力。
- 最近一次私密复盘；没有数据时显示明确空状态和进入练习的操作。

不显示回复率、约会数、联系方式数、恋爱数或身体关系数。

## 8. 情境库与首批数据

至少实现以下 8 个可完整游玩的场景：

1. 刚加好友后的第一轮聊天。
2. 对方提到兴趣后自然续聊。
3. 对方回复逐渐变短。
4. 清晰表达好感。
5. 发出一次具体且低压力的邀约。
6. 对方拒绝邀约后体面结束。
7. 初次约会中确认身体距离或亲吻意愿。
8. 对方饮酒、迟疑或改变主意时暂停推进。

至少三个场景必须直接训练拒绝或同意判断。每个场景至少包含：

- 唯一 `id`、标题、摘要、预计时长、难度。
- 关系阶段、渠道、目的、互动状态和风险标签。
- 虚构成人角色资料。
- 至少三个决策节点。
- 每个节点三个预设回应，其中包括合理、信息不足和有压力的表达。
- 至少两个结局，且对方可以拒绝或结束交流。
- 每个选项的五维影响、解释和边界提示。
- 一个自由输入任务、一次重试和两个复盘问题。
- 一个只评价用户行为的低压力现实练习。

所有静态场景必须通过 Zod schema 和图结构校验：起始节点存在、节点引用有效、全部节点可达、流程可结束、无意外死循环；危险选项必须带明确风险解释，拒绝或撤回同意后不能再出现推进关系的分支。

场景筛选包含关系阶段、渠道、目的和互动状态。移动端使用可关闭的筛选抽屉；桌面端使用侧边筛选区。筛选条件与结果数实时更新。

## 9. 模拟对话

### 9.1 界面

- 顶部显示场景名、当前节点和退出按钮。
- 角色区显示虚构头像、称呼和当前情境，不冒充真人。
- 对话区使用稳定高度和可滚动消息列表。
- 回应区允许在三个预设表达中选择，也允许输入自己的版本。
- 自由输入上限 240 字，并显示剩余字数。
- 键盘可完成选择、提交、返回和重试。

### 9.2 反馈

每次提交后展示：

1. 对方一种合理但不唯一的可能回应。
2. 做得好的地方。
3. 对方可能感受到的压力或信息缺口。
4. 五维中最相关的 2–3 项变化。
5. 一个关键修改和原因。
6. “重试此节点”与“继续”操作。

不要只给总分或“正确/错误”。分数只辅助解释，不能把人际互动伪装成确定公式。

### 9.3 场景结束

- 展示本次能力变化和一个边界判断总结。
- 让用户填写可选的私密复盘，默认只保存在本地。
- 提供“再练一次”“返回情境库”“保存复盘”。
- 完成记录应更新首页和进度页。

## 10. 消息实验室

### 10.1 输入

- 首屏固定脱敏提醒：不要输入姓名、电话、账号、地址或可识别第三方的信息。
- 必选关系阶段、沟通目的、对方回应状态。
- 草稿上限 600 字，默认不持久化。
- 提供三个可一键载入的安全示例，便于不输入真实内容也能体验功能。

### 10.2 本地诊断

建立纯函数 `analyzeMessage(context, text)`，返回结构化结果：

- `status`: `ok | caution | blocked`
- `strengths`
- `concerns`
- `scores`: 清晰、真诚、倾听、分寸、边界
- `rewritePrinciple`
- `examples`: 直接、轻松、稳重三种版本
- `stopCondition`

本地规则至少识别：

- 连续问号或过多问题造成的审问感。
- 大段自我输出但没有回应对方内容。
- 索取解释、情绪负债、反复催促和不容易拒绝的表达。
- 邀约缺少时间、地点或拒绝出口。
- 操控、欺骗、强迫、灌酒、纠缠、偷拍、未成年人、醉酒和权力差相关意图。

确定性规则只作为 MVP 互动演示。不要在界面声称它能准确理解全部语境或预测对方反应。

### 10.3 结果

- `ok`：展示优点、风险、修改原则和三种示例。
- `caution`：先展示压力或边界提示，再给低压力版本。
- `blocked`：不显示可执行的危险改写；简短拒绝，解释风险，给出停止、澄清或等待清醒等安全替代。
- 所有可复制示例旁必须显示“按自己的真实语气重写”，并提供一个自行重写输入框。
- 离开页面后原始草稿不应出现在 `localStorage`。

## 11. 安全策略实现

将安全判断做成独立、可测试的模块，不把规则散落在组件中。

建议类型：

```ts
type SafetyCategory =
  | 'manipulation'
  | 'deception'
  | 'coercion'
  | 'harassment'
  | 'intoxication'
  | 'minor'
  | 'powerImbalance'
  | 'privacyViolation';

type SafetyResult = {
  level: 'safe' | 'caution' | 'blocked';
  categories: SafetyCategory[];
  explanation: string;
  safeAlternative: string;
};
```

要求：

- 使用意图短语和组合规则，不只依赖单个敏感词。例如讨论“为什么不能灌酒”不应被误判为请求灌酒技巧。
- 被拦截时不能回显或扩写危险方案。
- 所有拒绝和亲密场景的数据都必须经过统一安全检查。
- 建立固定安全测试集，至少包含 12 个必须拦截、6 个谨慎提示、8 个正常内容样例。
- 双方均表达进一步亲密意愿时，只提示事前沟通避孕、性健康、隐私、舒适程度和随时暂停；不提供医疗判断或具体性行为技巧，正式健康文案需专业审核。

## 12. 数据模型与本地存储

建议核心类型：

```ts
type SkillKey = 'clarity' | 'authenticity' | 'listening' | 'pace' | 'boundaries';

type UserSettings = {
  isAdultConfirmed: boolean;
  selectedChallenges: string[];
  onboardingCompleted: boolean;
  reducedMotion: boolean;
};

type ProgressRecord = {
  scenarioId: string;
  completedAt: string;
  attempts: number;
  scores: Record<SkillKey, number>;
  boundaryCheckPassed: boolean;
};

type Reflection = {
  id: string;
  scenarioId: string;
  createdAt: string;
  text: string;
};
```

持久化要求：

- `localStorage` 使用带版本号的单一命名空间，并实现迁移或回退。
- 保存设置、进度、收藏和用户主动保存的复盘。
- 不保存消息实验室原始草稿和模拟对话自由输入原文。
- 导出 JSON 必须包含 schema 版本和导出时间。
- 清除数据需二次确认；确认后删除命名空间、重置状态并返回首次设置页。

## 13. 状态与细节

每个数据驱动页面都要有：

- 初始状态。
- 空状态。
- 校验错误状态。
- 无匹配筛选结果。
- 成功反馈。
- 可恢复的本地数据解析错误。

虽然首版没有远程请求，仍要避免伪造加载动画。场景切换可以使用 150–220ms 的轻微过渡，并尊重减少动态效果设置。

刷新、前进和后退后，路由与核心状态保持合理；表单错误不能只用弹窗提示。

## 14. 无障碍与响应式

- 页面主区域、导航、表单和对话记录使用正确语义元素。
- HTML 文档设置 `lang="zh-CN"`，正文默认字号不小于 16px。
- 对话更新使用合适的 live region，但避免每个装饰性变化都朗读。
- 模态框和移动筛选抽屉需要焦点圈定、Esc 关闭和关闭后焦点返回。
- 颜色对比达到 WCAG AA。
- 360×800、768×1024、1440×900 三个视口必须验证。
- 页面无横向滚动；底部导航、软键盘和安全区域不会遮挡提交按钮。
- 最长标签和错误文案不能溢出按钮、卡片或筛选项。
- 不加载第三方字体、追踪器或 CDN 脚本；默认运行不发送用户分析数据。

## 15. 测试要求

### 15.1 单元与组件测试

至少覆盖：

- 首次设置年龄门槛和步骤校验。
- 场景 schema、无效引用、不可达节点和无法结束流程。
- 推荐场景生成。
- 场景分支推进、重试和完成记录。
- 五维分数边界与聚合。
- 消息诊断的 `ok`、`caution`、`blocked` 三类结果。
- 所有安全类别的代表性样例。
- 原始草稿不进入本地存储。
- 数据导出和清除。
- 情境库多条件筛选。

### 15.2 端到端测试

至少覆盖：

1. 新用户完成首次设置并进入推荐练习。
2. 用户完成一个三节点场景、重试一次并保存复盘。
3. 消息实验室正常诊断并完成自行重写。
4. 危险意图被拦截，页面不出现危险改写。
5. 导出后清除数据，刷新仍回到首次设置。
6. 移动端打开筛选、选择场景并完成一个节点。

### 15.3 视觉验证

- 使用 Playwright 分别截取三个目标视口的首页、练习页和消息实验室。
- 检查图片非空、头像加载、焦点样式、长文案、底部导航和对话滚动区。
- 使用 axe-core 扫描核心页面，不能存在严重或致命问题。
- 检查控制台无运行时错误、资源 404 或 React key 警告。

## 18. 禁止用占位实现代替的部分

- 不得用静态截图冒充可交互对话。
- 不得让所有场景共用同一段内容或同一条直线流程。
- 不得让按钮点击后无反应、仅打印日志或显示“即将上线”。
- 不得用随机数冒充能力分析。
- 不得用外部图片 URL 冒充本地资产。
- 不得把安全规则写成一段不可执行的免责声明。
- 不得为了视觉效果牺牲移动端可用性、文本可读性或对比度。

完成编码后，先自行运行全部测试和生产构建，再启动本地开发服务器并提供可访问地址与验证结果。
