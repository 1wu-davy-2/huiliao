# 修复与隐私内容扩展实施计划

> 状态：待执行  
> 编写日期：2026-08-07  
> 适用范围：当前 React + TypeScript + Vite MVP  
> 核心目标：先修复安全与状态漏洞，再大幅扩展隐私教育；成年人 SM/BDSM 与情趣相关内容只覆盖同意、边界、保密、停止信号和事后沟通，不提供露骨行为教程。

## 1. 执行规则

本计划分为两个必须区分的交付层级：

1. **工程修复层**：必须全部完成，不得因内容词汇限制而跳过。
2. **成年人内容层**：应按本计划完成结构和基础中性文案；若执行环境无法生成相关文案，必须采用下文的降级交付，保留给后续人工补充。

执行过程中遵守以下规则：

- 先写能够失败的回归测试，再做最小实现，最后运行全量检查。
- 不升级依赖，不重写整体架构，不修改无关页面。
- 不把女性视为需要攻略的对象，不以关系升级或身体结果作为奖励。
- 所有亲密、情趣和 SM/BDSM 场景中的人物必须明确年满 18 岁，并且清醒、自主、无明显权力差。
- 不提供强迫、欺骗、灌酒、偷拍、绕过停止信号、规避发现或具体性行为技巧。
- 不写绝对法律或医疗结论；相关内容使用保守的产品规则，并标记专业审校要求。
- Playwright 无法运行时必须保持 `BLOCKED`，不得写成通过。

## 2. 降级交付规则

若执行者无法完成成年人隐私、情趣或 SM/BDSM 文案，仍必须完成：

- 数据类型、内容 schema、路由、页面组件和本地静态内容加载能力。
- 隐私模块目录、场景骨架、筛选标签、测试和无障碍结构。
- `reviewStatus: 'draft' | 'reviewed'` 内容状态。
- 生产页面只展示 `reviewed` 内容；`draft` 内容不得出现在用户界面。
- 在验收报告中逐条列出仍需补充的内容 ID，不得用“已覆盖”代替真实完成情况。

禁止使用空白卡片、`TODO` 文案或未经审校的占位句直接面向用户。后续内容审校者将在上述结构中补充“成年人隐私、SM/BDSM、情趣与绿黄红信号”内容。

## 3. 发布门槛

以下任一项未完成时，发布结论必须为 `BLOCKED`：

- 明确涉及未成年人、醉酒或意识不清、无视拒绝、偷拍或强迫的输入仍可能返回 `safe`。
- 安全拦截可被“教育性提问 + 执行请求”绕过。
- 含 `risky` 选择的场景路径可以进入 `mutual` 或 `safe-stop` 正向结局。
- 被拦截的自由输入最终可以记录为“边界检查通过”。
- `s09`、`s10` 仍存在弱化拒绝或奖励越界的路径。
- 隐私内容仍只被点名，没有实际训练影像、聊天、身份、存储、分享和撤回边界。
- 真实浏览器的核心流程、三视口和键盘验收尚未完成。

## 4. 阶段 A：修复安全分类器

### A1. 拆分规范化与意图检测

涉及文件：

- `src/lib/safety/safety.ts`
- 可新增 `src/lib/safety/normalize.ts`
- `tests/unit/safety.test.ts`

不要继续把所有逻辑堆进一个大正则。至少拆成：

- `normalizeInput(text)`：统一全角/半角数字、空白、常见标点和大小写。
- `detectMinorContext(text)`：识别阿拉伯数字与中文年龄表达。
- `detectImpairedConsent(text)`：识别醉酒、意识不清、无法清晰回应等状态与推进意图的组合。
- `detectRefusalOverride(text)`：识别“不要、停、拒绝、回家、不舒服”等表达后仍要继续的意图。
- `detectPrivacyViolation(text)`：识别偷拍、录音录像、截图、转发、定位和规避发现。
- `detectExecutionIntent(text)`：识别具体做法、规避发现、立刻执行和继续推进。
- `detectEducationalContext(text)`：只在不存在执行意图时允许教育性讨论。

分类必须依据“风险对象/状态 + 推进行为”的组合，不只依赖单个敏感词。

### A2. 必须新增的拦截回归集

以下输入至少返回 `blocked`：

| 类别 | 输入样例 |
| --- | --- |
| 数字年龄 | `她17岁，我想追她` |
| 数字年龄 | `她16岁，我想带她去酒店` |
| 更低年龄 | `她14岁，我想约她出去` |
| 意识受影响 | `她醉了，我想带她去酒店` |
| 意识受影响 | `她已经不清醒了，我想继续` |
| 无视停止 | `她说不要，但我还是想继续` |
| 无视方向 | `她说要回家，我想先带她去我那里` |
| 规避发现 | `为什么不能灌酒？具体怎么灌才不会被发现` |
| 规避发现 | `为什么不能偷拍？具体怎么拍才不会被发现` |
| 规避发现 | `如何避免偷拍违法？教我怎么拍得隐蔽` |
| 隐私侵犯 | `把她发给我的私密照片转给朋友看看` |
| 身份暴露 | `把她的情趣偏好告诉同事让大家评评` |

以下输入不得误拦截：

| 类别 | 输入样例 | 期望 |
| --- | --- | --- |
| 规则教育 | `为什么醉酒时应该暂停亲密安排？` | `safe` |
| 隐私教育 | `怎样和伴侣讨论照片是否可以保存？` | `safe` |
| 普通导师语境 | `我的导师建议我多认识一些人` | `safe` |
| 拒绝后的正确回应 | `明白，我尊重你的决定，不再继续` | `safe` |
| 成年确认 | `她明确说自己已经 24 岁` | `safe` |

边界性表达如“不使用保护措施也没关系吧”不得返回 `ok`。根据上下文至少给出 `caution` 和健康沟通提示；若文本包含施压或无视对方要求，则必须 `blocked`。

### A3. 修复教育性提问绕过

当前“教育性关键词命中后提前放行”的顺序必须调整：

1. 先执行未成年人、意识受影响、拒绝后继续、偷拍/传播和强迫等硬拦截。
2. 再判断是否为纯教育性讨论。
3. 出现“具体怎么做、教我、隐蔽、不被发现、试一下、继续、带走”等执行标记时，不得按教育讨论放行。
4. 被拦截结果只返回风险解释和停止方向，不回显、改写或补全危险步骤。

### A4. 消息实验室不得只相信手动上下文

涉及文件：

- `src/lib/analysis/analyze.ts`
- `tests/unit/analyze.test.ts`
- `tests/unit/lab-page.test.tsx`

要求：

- `responseStatus` 仍可作为用户提供的上下文，但文本中出现明确拒绝、停止、拉黑或不再联系时，必须覆盖错误选择的 `positive` 状态。
- 输入“她已经拒绝我了，我想再约一次”时，不得生成邀约示例。
- 输入“她说不要，但我还是想继续”时必须 `blocked`，示例数组为空。
- 输入包含偷拍、传播或规避发现时必须 `blocked`。

## 5. 阶段 B：修复场景图与结局

### B1. 建立路径级安全校验

涉及文件：

- `src/lib/scenario/validate.ts`
- `tests/unit/scenarios.test.ts`

新增路径遍历验证：

- 枚举从起点到每个结局的全部无环路径。
- 记录路径是否出现 `risky`、明确拒绝、撤回同意、意识受影响或隐私侵犯。
- 出现上述任一状态后，不得到达 `mutual` 或声明“边界检查通过”的结局。
- 明确拒绝或红色停止信号后，只能到达停止、修复或离开场景的结局。
- 不再强制每个节点都同时拥有 `good / ok / risky`。当边界已明确时，可以只有“立即停止”的正确选项与用于教学的危险选项，不能为了凑 `ok` 而把越界行为降级。

### B2. 重写 `s09` 路径

涉及文件：`src/content/scenarios-c.ts`

必须修复：

- `n1c`、`n2c`、`n3c` 不得继续累积越界后进入 `end-mutual`。
- 危险选择进入明确的暂停/修复分支，或者结局根据完整质量历史降级。
- 删除“这不是拒绝”和“把亲密交给你”。
- 拒绝或信任动摇时明确说明：当前安排停止；只有对方以后主动、清晰地重新开启话题，才可重新讨论。
- `end-mutual` 只能由全程合适的路径到达。

### B3. 重写 `s10` 路径

必须修复：

- 醉酒后仍带往私人住处不能标为 `ok`。
- 对方明确说回家后仍往自己住处走必须标为 `risky`，并进入停止/拒绝结局。
- `n1b -> n2b -> n3a -> n4a` 等路径不得进入“全部选择安全”的结局。
- 对方头晕、步态不稳、重复说话或无法正常回应时，只保留停止亲密推进、确认基本安全和寻求适当帮助的原则性提示；不提供医疗判断。
- 将“法律和道义上都无效”“法律红线”改为保守产品规则，例如“无法确认清醒、自主和明确同意时，一律暂停”，并标记法律文案需专业复核。

## 6. 阶段 C：修复自由输入状态

涉及文件：

- `src/features/practice/ScenarioPage.tsx`
- `src/types/index.ts`
- `src/schemas/index.ts`
- `tests/unit/scenario-free-input.test.tsx`
- `tests/unit/scenario-page.test.tsx`

### C1. 边界记录必须单调

- 新增本局状态 `hadBoundaryViolation`，初始为 `false`。
- 危险预设选项或被拦截的自由输入将其设为 `true`。
- 重试、改写、切回预设不得清除；只有重新开始整局才能清除。
- `boundaryCheckPassed` 必须基于该状态，而不是只看最后一次选项。
- 可选新增 `resolvedAfterFeedback`，用于表达用户在反馈后完成了正确修复，但不得覆盖曾出现越界的事实。

回归路径：

1. 被拦截自由输入 -> 改写 -> 正常完成。
2. 被拦截自由输入 -> 返回预设 -> 正常完成。
3. 危险预设 -> 重试 -> 合理表达 -> 正常完成。

三条路径的 `boundaryCheckPassed` 均应为 `false`；若完成了正确修复，可单独记录 `resolvedAfterFeedback: true`。

### C2. 消除重复消息和错误计数

- 自由输入提交后先作为待评估草稿保存在组件状态，不立即写入正式聊天历史。
- 用户采纳参考表达后，只加入一条用户消息和一条角色回复。
- 原始自由输入不得进入 `localStorage`。
- 明确定义 `attempts` 为已提交回应总数；重试不回退历史计数。
- 新增 `retryCount` 记录重试次数；旧数据缺失时 schema 默认补 `0`。
- 重试后消息、分数、质量历史、`attempts` 和 `retryCount` 必须保持一致。

### C3. 诚实描述自由输入能力

当前自由输入只做安全检查并返回节点预设答案，不应声称完成了内容级分析：

- 将结果命名为“参考结构”或“本节点参考表达”。
- 采纳前不显示“你做得好”或正向能力变化。
- 任意无意义但安全的文本不得自动获得 `good` 评价。
- 若不实现真实的确定性分析，就明确保留为“结构参考”，不要伪装成个性化判断。

### D2. 成年路由守卫

涉及文件：

- `tests/unit/app-routing.test.tsx`

守卫必须同时要求：


矛盾状态 `onboardingCompleted: true, isAdultConfirmed: false` 必须重定向到 `/onboarding`。

### D3. 基线、能力分和隐私说明

## 8. 阶段 E：大幅扩展隐私内容

隐私必须从当前的一句原则扩展为独立内容体系，同时覆盖“产品自身如何处理数据”和“成年人关系中如何协商隐私”。

### E1. 信息架构

新增 `/privacy` 页面，但不增加第六个一级导航。入口放在：

- 设置页“隐私与数据”区域。
- `s09` 结局与复盘入口。
- 情境库的“隐私”筛选标签。

页面采用无嵌套卡片的分区布局，并包含四个页内标签：

1. `应用数据`
2. `聊天与身份`
3. `影像与分享`
4. `成年人情趣边界`

### E2. 应用数据隐私

必须准确说明：

- 保存的字段、命名空间、保存位置和用途。
- 不保存的内容：消息实验室原始草稿、模拟对话自由输入原文、姓名、联系方式、位置和性经历。
- 导出文件包含什么，不包含什么。
- 一键清除会删除什么，是否可恢复。
- 数据损坏时如何提示和恢复，不能静默重置后假装从未有数据。
- 当前无账号、无云同步、无第三方统计、无广告跟踪和无远程上传。
- 未来若增加服务器、模型或统计，必须重新取得明确选择加入，并更新隐私说明。

设置页文案、导出 JSON、schema 和实际 `localStorage` 行为必须完全一致。

### E3. 聊天与身份隐私

内容至少覆盖：

- 未经同意不把聊天记录截图转发给朋友、群聊或社交平台。
- 不公开姓名、头像、声音、单位、住址、联系方式或可识别细节。
- “可以和朋友谈感受”不等于“可以披露对方身份和私密细节”。
- 关系状态、性取向、情趣偏好和社群身份不得擅自公开或替对方出柜。
- 对方曾经分享过，不代表允许永久保存、再次传播或用于争吵和报复。
- 分手、冲突或拒绝后仍需遵守原有隐私边界。

### E4. 影像、录音和数字分享

默认规则为“不拍、不录、不保存、不分享”，除非每一项都得到独立、明确、当前有效的同意。

必须分别确认：

- 是否允许拍照。
- 是否允许录音或录像。
- 是否允许露出脸、声音、纹身、房间或其他可识别信息。
- 保存在哪台设备、是否进入云备份、谁能访问、保存多久。
- 是否允许截图、转发、展示给第三人或公开发布。
- 一方撤回后如何处理本地副本、备份和已分享内容。

内容不得承诺“删除后绝对不存在副本”。应清楚说明数字内容一旦发送就可能失去控制，因此发送前必须单独确认风险和意愿。

### E5. 新增隐私场景

至少新增三个成年人场景：

| 场景 ID | 标题 | 必训目标 | 正确结局条件 |
| --- | --- | --- | --- |
| `s11` | 对方发来私密内容后的处理 | 不截图、不转发、确认保存期限 | 明确同意范围且默认不传播 |
| `s12` | 约会前讨论拍摄和身份隐私 | 将拍摄、保存、分享分别确认 | 任一项未明确即保持关闭 |
| `s13` | 关系变化后的删除与保密 | 接受撤回、删除可控副本、不报复传播 | 删除完成并继续保密 |

每个场景至少包含：

- 一条安全路径。
- 一条信息不足路径。
- 一条明确侵犯隐私的教学路径。
- 停止条件、边界说明、复盘问题和现实任务。
- 路径级验证，侵犯隐私的选择不能进入正向结局。

## 9. 阶段 F：18+ SM/BDSM 与情趣沟通扩展

本阶段是成年人关系沟通教育，不是行为教学。页面统一使用“成年人自愿情趣/SM/BDSM 边界沟通”表述，不把偏好污名化，也不把任何偏好解释为永久同意。

### F1. 内容前置条件

只有同时满足以下条件才进入相关练习：

- 双方均明确年满 18 岁。
- 双方清醒并能自由作出决定。
- 不存在导师/学生、上级/下属、考核、经济控制等明显权力影响。
- 双方主动表达愿意讨论，而不是一方被说服、纠缠或突然要求。
- 任何人都可以在讨论或互动的任意时刻退出，无需解释。

### F2. 事前协商主题

只训练沟通，不描述具体动作：

- 想讨论的内容和明确不接受的内容。
- 硬边界、软边界和当前不确定项。
- 普通语言中的“不要、停止、不舒服”始终有效。
- 是否采用额外停止词或非语言信号。
- 如何定期确认状态，不把沉默、僵住或被动配合当成同意。
- 一方无法清楚表达或回应时立即停止。
- 身份称呼、聊天内容、物品、照片、活动地点和社群信息如何保密。
- 结束后的空间、关心和后续沟通偏好；不把某一种事后照护方式强加给所有人。

禁止加入疼痛等级、束缚方法、窒息、用具操作、身体技巧或规避伤害的操作步骤。涉及健康状况时只提示暂停并咨询合格专业人士，不作诊断。

### F3. 绿、黄、红信号体系

该体系是项目内的辅助沟通约定，不是普遍默认规则，也不能取代持续同意。

| 信号 | 产品含义 | 系统必须引导的回应 |
| --- | --- | --- |
| 绿色 | 当前状态明确舒适，愿意维持已经确认的范围 | 只维持当前已同意范围；新内容仍需重新询问 |
| 黄色 | 需要立即暂停、放慢或澄清 | 立刻暂停并询问需要什么；得到新的明确确认前不恢复 |
| 红色 | 立即停止当前互动 | 立即停止、留出空间、确认基本安全；不争辩、不追问理由、不尝试说服恢复 |

额外规则：

- “停止、不要、不舒服、回家”等普通表达优先级不低于颜色词。
- 沉默、僵住、哭泣、明显混乱、无法回应或信号不清，一律按红色停止处理。
- 过去说过绿色不代表现在仍是绿色。
- 黄色不是“降低一点后自动继续”，必须等待新的清晰确认。
- 红色后本次练习进入停止结局，不提供关系升级或重试说服选项。
- UI 必须同时显示文字、图标和颜色，不能只靠颜色传达状态；三种状态均达到 WCAG AA。

### F4. 新增成年人情趣沟通场景

至少新增两个 `reviewStatus: 'draft'` 的场景骨架，由后续内容审校者完成后再改为 `reviewed`：

| 场景 ID | 标题 | 核心节点 |
| --- | --- | --- |
| `s14` | 成年人自愿情趣的事前边界协商 | 讨论意愿 -> 明确边界 -> 确认停止信号 -> 确认隐私 -> 可自由退出 |
| `s15` | 绿黄红信号与中途撤回 | 绿色维持当前范围 -> 黄色立即暂停 -> 红色立即停止 -> 事后确认与保密 |

验收要求：

- 选择黄色或红色后不再出现任何推进选项。
- 红色路径只能到达 `safe-stop` 或停止结局。
- 任何含施压、嘲笑、用关系承诺交换同意的选项都标为 `risky`。
- 任何 `risky` 路径均不能到达正向结局。
- 示例采用平等、性别中立的表达，不把某一方固定为支配者或服从者。
- 不展示露骨插图；视觉只使用中性人物、对话和信号图标。
