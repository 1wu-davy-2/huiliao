# 项目部署架构修改确认计划

> 状态：技术适配已实施；Preview 与 Production 仍待确认
> 编写日期：2026-08-07  
> 目标平台：Vercel  
> 当前架构：React 18 + TypeScript + Vite 5 + React Router 6，纯前端 SPA，用户训练数据保存在浏览器 `localStorage`

> 2026-08-07 状态更新：项目现已建立 Git 仓库并配置 `origin`，Vercel 配置、Node 22 声明、部署校验脚本和安全响应头已落地。下文“当前目录不是 Git 仓库”等内容保留为制定计划时的基线，不代表本轮结束时的状态；最新结果以 [验收报告](./ACCEPTANCE_REPORT.md) 为准。

## 1. 结论

当前项目**可以部署到 Vercel**，无需改造成 Next.js、SSR 或服务器应用。建议继续保持纯静态 SPA 架构，由 Vercel 构建 `dist/` 并通过 CDN 分发。

但当前版本还不能直接作为公开生产版本发布，原因包括：

- 缺少 Vercel SPA 深层路由重写，直接访问 `/practice/s02` 等路径可能返回 404。
- 缺少部署配置、安全响应头、Node 版本锁定与部署验收脚本。
- 当前目录不是 Git 仓库，无法直接采用推荐的 Git 自动部署流程。
- 当前本机 Node.js 为 `20.16.0`，而首次 Vercel 部署需要选择并验证较长期可用的 Node 版本。
- 隐私说明没有区分“训练数据不上传”和“托管平台仍会处理 HTTP 请求元数据”。
- 前一轮安全、同意和内容审查仍有发布阻断项；部署能力可以先完成，但生产发布必须等待修复验收。
- 后续成年人 SM/BDSM 内容必须保持教育性、非露骨、非图像化，并再次核对 Vercel 当时有效的可接受使用政策。

推荐结论：

1. 先完成 Vercel 架构适配。
2. 部署一个受保护的 Preview 环境进行真实浏览器验收。
3. 修完安全与内容阻断项。
4. 绑定稳定自定义域名后再发布 Production。

## 3. 目标部署架构

```text
GitHub / GitLab / Bitbucket
          |
          | push / pull request
          v
Vercel Preview Build
  - Node.js 22.x
  - npm ci
  - lint + unit tests + build
          |
          v
        dist/
          |
          v
Vercel CDN + HTTPS + security headers
          |
          v
Browser
  - React SPA
  - static content
  - localStorage: huiliao:v1
  - no app API / no database / no user draft upload
```

架构原则：

- Vercel 只负责构建和分发静态文件。
- 不为当前 MVP 增加 Serverless Function、数据库、账号或云同步。
- 不在 Vercel 日志中主动记录消息草稿、情境自由输入或复盘内容。
- 所有业务数据继续留在当前浏览器 origin 下。
- 保持 `dist/` 为标准静态产物，使项目仍可迁移到其他静态托管平台。

## 4. 架构决策

### ADR-001：继续使用静态 SPA

结论：确认。

理由：

- 当前没有服务端数据、用户账号或动态页面需求。
- 改为 SSR 不会改善核心训练功能，反而增加函数、日志、隐私和成本边界。
- Vercel 官方支持 Vite SPA；只需给深层路由增加 `index.html` rewrite。

### ADR-002：以 Git 集成为正式部署方式

结论：推荐确认。

- 每个分支或 Pull Request 生成独立 Preview。
- `main` 作为 Production 分支。
- 只有通过验收的 Preview 才允许合并到 `main`。
- Vercel CLI 只作为首次联调、故障排查或 Git 尚未建立时的临时方式。

当前目录没有 `.git`，因此正式实施前必须由项目所有者选择 Git 托管平台并建立远程仓库。计划本身不执行初始化、提交或远程推送。

### ADR-003：锁定 Node.js 22.x

结论：推荐确认。

- 不继续锁定即将退出 Vercel支持周期的 Node.js 20。
- 不直接依赖 Vercel默认 Node.js 24，以减少首次部署与本机 Node 20 的跨度。
- 在 Node.js 22 下重新执行 `npm ci`、lint、测试和构建后，再写入 `package.json`。
- 后续升级 Vite 和测试工具后，可单独评估 Node.js 24。

### ADR-004：默认关闭分析与第三方脚本

结论：确认。

- 不启用 Vercel Web Analytics、Speed Insights、广告脚本或第三方聊天工具。
- 不添加第三方字体或 CDN 脚本。
- 如果未来启用统计，必须先更新隐私说明、CSP 和选择加入机制。

### ADR-005：使用稳定自定义域名作为数据 origin

结论：推荐确认。

`localStorage` 按 origin 隔离：

- Preview URL、`*.vercel.app` 和自定义域名互不共享训练进度。
- 从临时域名切换到正式域名不会自动迁移数据。
- 上线真实用户前应尽早确定永久域名。
- 域名更换前必须提醒用户导出数据；新域名提供导入能力后才能迁移。

## 5. 必须修改的文件

### 5.1 新增根目录 `vercel.json`

建议配置：

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": "vite",
  "installCommand": "npm ci",
  "buildCommand": "npm run verify:deploy",
  "outputDirectory": "dist",
  "trailingSlash": false,
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ],
  "headers": [
    {
      "source": "/assets/(.*)",
      "headers": [
        {
          "key": "Cache-Control",
          "value": "public, max-age=31536000, immutable"
        }
      ]
    },
    {
      "source": "/(.*)",
      "headers": [
        {
          "key": "Content-Security-Policy",
          "value": "default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none'; form-action 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; media-src 'self'; worker-src 'self'; manifest-src 'self'"
        },
        {
          "key": "X-Content-Type-Options",
          "value": "nosniff"
        },
        {
          "key": "X-Frame-Options",
          "value": "DENY"
        },
        {
          "key": "Referrer-Policy",
          "value": "no-referrer"
        },
        {
          "key": "Permissions-Policy",
          "value": "camera=(), microphone=(), geolocation=(), payment=(), usb=()"
        }
      ]
    }
  ]
}
```

实施注意：

- 使用 `rewrites`，不要再同时配置旧式 `routes`，两套配置可能冲突。
- 不设置 `cleanUrls: true`，避免将 `/index.html` rewrite 改成不同语义。
- catch-all rewrite 必须验证不会把真实 JS、CSS、SVG 请求错误返回成 HTML。
- CSP 中暂时保留 `style-src 'unsafe-inline'`，因为当前代码使用 React 内联样式；以后消除内联样式后再收紧。
- 严格 CSP 可能阻止 Vercel Preview Toolbar。不得为了工具栏放宽生产 CSP；优先关闭工具栏或只在明确审查后增加环境特例。
- 只给带内容哈希的 `/assets/` 设置一年浏览器缓存；`/images/` 文件名未带哈希，不使用 `immutable`。
- `index.html` 保持 Vercel默认的重新验证策略，避免新部署后浏览器长期使用旧入口。

### 5.2 修改 `package.json`

目标结构：

```json
{
  "engines": {
    "node": "22.x"
  },
  "scripts": {
    "verify:deploy": "npm run lint && npm run test && npm run build"
  }
}
```

要求：

- 保留现有脚本，不覆盖 `dev/test/build/e2e`。
- 在 Node.js 22 环境验证通过后再提交 `engines`。
- `verify:deploy` 不运行 Playwright；浏览器依赖下载失败不能阻断静态构建，但 E2E 状态必须单独如实记录。
- 若未来已有独立 CI，可将 Vercel `buildCommand` 恢复成 `npm run build`，但前提是 Production 分支受 CI 必过保护。

### 5.3 修改 `.gitignore`

追加：

```gitignore
.vercel/
```

`.vercel/` 保存本地目录与 Vercel项目的链接信息，不进入版本库。

### 5.4 新增 `.vercelignore`

建议最小内容：

```gitignore
dist/
coverage/
test-results/
playwright-report/
blob-report/
*.local
```

说明：

- `dist/` 由 Vercel 在干净环境重新构建，不上传本机旧产物。
- 不忽略 `tests/`，因为推荐的 `verify:deploy` 需要运行单元与组件测试。
- 不忽略 `public/`、`src/`、配置文件和锁文件。
- `node_modules/` 通常由平台默认排除并重新安装，不上传本机依赖。

### 5.5 更新 README

新增“Vercel 部署”章节，至少说明：

- Framework Preset：Vite。
- Install Command：`npm ci`。
- Build Command：`npm run verify:deploy`。
- Output Directory：`dist`。
- Node.js：22.x。
- 深层路由由 `vercel.json` rewrite 支持。
- Preview 与 Production 的数据按域名隔离。
- 当前没有服务端 API、数据库或环境变量。
- Playwright 未执行时不能把 E2E 写成通过。

## 6. 隐私架构需要同步修改

部署到 Vercel 后，“不会上传任何数据”不是完整准确的描述。应拆成两层：

### 6.1 应用内容数据

- 消息实验室草稿、模拟对话自由输入和复盘仍不得发送给 Vercel Function 或第三方 API。
- 当前应用没有 Function、数据库或云同步。
- 训练进度和设置只存放在访问该域名的浏览器 `localStorage`。
- Vercel部署日志不得由项目代码主动写入用户输入。

### 6.2 基础设施请求数据

用户访问网站时，托管平台必然处理提供静态文件所需的请求数据，例如 IP、User-Agent、请求路径、时间和安全检测信息。隐私说明应明确：

- “训练内容不上传”不等于“访问网站完全没有网络请求”。
- 静态文件由 Vercel CDN 提供，基础请求元数据由托管平台按其政策处理。
- 项目默认不开启额外的 Web Analytics 和 Speed Insights。
- 提供 Vercel Privacy Notice 链接和项目自身的联系/反馈方式。

还需确认 Vercel账户设置中的可选模型训练配置。若项目内容不希望进入平台模型训练，应在团队/项目设置中明确关闭，并保存设置截图作为上线记录。

## 7. 环境变量与密钥规则

当前部署不需要任何环境变量。

硬性规则：

- 不创建只有占位值的 `.env.example`。
- `VITE_*` 会进入前端构建产物，不能放 API Key、Token、密码或管理凭据。
- 未来若增加后端密钥，只能存在 Vercel环境变量和服务端 Function 中，不能由浏览器读取。
- Preview、Production 环境变量必须分开配置。
- 禁止把 Vercel Token 写进仓库、Markdown、构建日志或前端代码。
- `.env.local` 继续由 `*.local` 规则忽略。

可选的非敏感构建变量：

- `VITE_DEPLOY_ENV=preview|production`
- `VITE_APP_VERSION=<commit-sha>`

只有在页面确实需要显示版本或按环境设置 robots 时才增加，不为“看起来完整”而新增。

## 8. Preview、Production 与访问控制

### 8.1 Preview

- 使用 Vercel Authentication 保护 Preview。
- Preview 默认 `noindex, nofollow`。
- 只向测试者分享受控链接。
- 不使用 Preview URL 作为长期用户入口。
- 测试数据仅属于该 Preview origin，部署销毁前先导出需要保留的数据。

### 8.2 Production

- 前一轮安全与内容发布阻断项全部修复后才能公开。
- 保留应用内 18+ 首次确认；它是产品准入说明，不是强身份验证。
- 使用稳定自定义域名。
- 生产域名公开前再次检查内容政策、隐私说明和 robots 策略。
- 初次小范围发布可先设置 `noindex, nofollow`；通过内容和合规审查后再决定是否允许搜索引擎收录。

### 8.3 域名

推荐：

- 使用 `www.example.com` 作为主域名。
- apex 域名重定向到 `www`。
- 在确认最终域名后添加 canonical URL。
- 由 Vercel自动签发和续期 HTTPS 证书。
- 不自行设置 HSTS preload；只有确认所有子域长期支持 HTTPS 后再单独评估。

## 9. 平台方案与商业使用确认

上线前必须确认使用性质：

| 使用方式 | 推荐计划 |
| --- | --- |
| 个人学习、内部原型、完全非商业 | 可评估 Hobby |
| 收费、广告、会员、商业推广、公司项目 | Pro 或更高计划 |
| 需要生产密码保护、专用支持或高级安全控制 | 按 Vercel最新计划能力评估 |

Vercel当前明确把 Hobby 限定为个人、非商业使用。产品一旦收费、投放广告、为业务引流或由公司运营，不得继续把 Hobby 当作默认生产方案。

还应确认：

- 月度 CDN 请求和流量额度。
- Preview 保护能力是否满足测试需要。
- 部署保留时间是否满足回滚周期。
- 账号所有者、账单联系人和域名所有权。
- 是否关闭 Hobby/试用账户中默认开启的可选模型训练。

## 10. 成年内容与 Vercel政策门槛

Vercel当前可接受使用政策禁止违法、性剥削、虐待、非自愿私密影像，以及冒犯性、淫秽或图像化内容。项目应保持为**非露骨的成年人沟通教育产品**：

- 不使用露骨性行为图片、视频或动画。
- SM/BDSM 内容只讨论成年人自愿、隐私、边界、绿黄红停止信号和事后沟通。
- 不提供身体技巧、危险操作、伤害规避方法或“18禁资源”。
- 不允许用户上传图片、视频或真实聊天记录。
- 不建立公开社区或用户生成内容区。
- 不出现未成年人相关亲密内容。
- 不托管或传播非自愿私密影像。

在 `s14/s15` 从 `draft` 改成 `reviewed` 前：

1. 重新打开当时有效的 Vercel Acceptable Use Policy。
2. 对最终文案和视觉资产做内容政策检查。
3. 如存在不确定性，在公开生产部署前向 Vercel取得书面确认，或保留其他静态托管方案。

技术部署成功不等于平台政策审查通过。

## 11. 中国大陆访问风险

项目目标用户包含中国大陆用户时，Vercel不能被视为有可用性保证的境内部署方案。

已知架构事实：

- Vercel没有中国大陆境内 CDN 节点，也不提供 ICP 备案或境内托管支持。
- `.vercel.app` 域名可能出现高延迟、限速或不可访问。
- 自定义域名可以降低部分域名层面的风险，但不能保证网络质量。

发布前至少从以下网络实测：

- 中国电信。
- 中国联通。
- 中国移动。
- 家庭宽带与移动网络。
- Android 与 iOS 浏览器。

检查 DNS、TLS、首页 HTML、JS/CSS、头像资源和首次可交互时间。不得只用香港或海外网络结果代表大陆体验。

若大陆用户是主要受众且实测不达标：

- 保持同一 `npm run build -> dist/` 静态产物规范。
- 评估另一个具备大陆合规条件的静态镜像，而不是把不透明反向代理直接套在 Vercel前面。
- 境内部署需另行处理 ICP、内容、公安联网备案及当地法律要求。
- 双部署会形成不同 origin，`localStorage` 不会自动共享；必须提前设计导出/导入和域名迁移方案。

## 12. 部署前自动检查

在 Node.js 22 环境中执行：

```powershell
npm ci
npm run lint
npm run test
npm run build
```

检查产物：

```powershell
Get-ChildItem -Recurse -File dist
```

必须确认：

- `dist/index.html` 存在。
- `dist/assets/*.js` 和 `*.css` 存在且文件名带哈希。
- `dist/images/avatars/*.svg` 全部存在。
- 构建产物没有 `.env`、Token、Key 或本机绝对路径。
- HTML 中入口资源使用 `/assets/...`，适合根域部署。
- bundle 不包含草稿内容或 `reviewStatus: draft` 场景。

建立 Git/Vercel链接后再执行：

```powershell
npx vercel@latest link
npx vercel@latest build
npx vercel@latest
```

这些命令会改变本地 `.vercel/` 状态并创建远程部署，必须由项目所有者明确授权后执行。本计划只记录命令，不执行部署。

## 13. Preview 验收清单

### 13.1 HTTP 与 SPA 路由

以下地址必须直接打开、刷新后仍返回 200：

- `/`
- `/onboarding`
- `/practice`
- `/practice/s02`
- `/practice/s09`
- `/practice/s10`
- `/lab`
- `/progress`
- `/settings`
- `/privacy`（隐私扩展完成后）

同时确认：

- 页面响应 `Content-Type` 为 `text/html`。
- `/assets/*.js` 返回 JavaScript，不是 `index.html`。
- `/assets/*.css` 返回 CSS，不是 `index.html`。
- `/images/avatars/qing.svg` 返回 `image/svg+xml`。
- 随机未知路径由 SPA 接管并显示应用内兜底，不出现 Vercel 404。

### 13.2 安全响应头

检查每个代表路由都包含：

- `Content-Security-Policy`
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: no-referrer`
- `Permissions-Policy`

浏览器控制台不得出现会阻断应用的 CSP 错误。重点检查：

- React 入口脚本。
- CSS 与 React 内联样式。
- 本地 SVG 头像。
- 导出 JSON 下载。
- Vercel Preview Toolbar 是否被阻止；工具栏失败不能作为放宽生产 CSP 的理由。

### 13.3 本地数据

- 完成首次设置后刷新，数据仍存在。
- 深层路由刷新不清除进度。
- 导出文件成功下载。
- 清除数据后刷新仍回到首次设置。
- Preview A、Preview B 与 Production 的数据互相隔离。
- 域名变化前的导出文件能够在计划支持导入后迁移；未实现导入前必须明确提示不能自动迁移。

### 13.4 三视口与无障碍

- 360x800。
- 768x1024。
- 1440x900。
- 键盘完成首次设置、一个普通场景、一个拒绝场景和设置页操作。
- 移动底部导航不遮挡最后一个操作按钮。
- CSP、rewrite 或域名变化不导致图片 404。

## 14. Production 发布流程

1. 安全与内容修复计划全部通过。
2. Node.js 22 下全量自动检查通过。
3. 推送功能分支，生成受保护 Preview。
4. 完成 Preview HTTP、浏览器、三视口、键盘和内容验收。
5. 检查 Vercel计划、AUP、隐私和大陆访问风险。
6. 合并到 `main`，由 Vercel生成 Production deployment。
7. 先验证生成的 Production URL，不立即切换主域名。
8. 验证通过后绑定或提升到自定义域名。
9. 检查 DNS、HTTPS、canonical、robots 和安全头。
10. 发布后 30 分钟、24 小时和 7 天分别复查可用性与错误。

Production 上线验收证据至少包括：

- Vercel deployment URL 与 deployment ID。
- Git commit SHA。
- 构建日志摘要。
- 自动测试数量和结果。
- 深层路由 HTTP 结果。
- 安全响应头结果。
- 三视口截图。
- 内容/AUP/隐私复核记录。
- 回滚目标 deployment ID。

## 15. 回滚与本地数据兼容

Vercel可以把域名重新指向之前的部署，但应用的 `localStorage` 不会随代码回滚。

这对当前项目尤其重要：

- 新版本可能写入更高 `schemaVersion`。
- 回滚到旧代码后，旧代码可能无法解析新数据。
- 当前解析失败会静默回到默认数据，用户可能误以为进度被删除。

因此每次修改存储 schema 前必须：

1. 编写旧版 -> 新版迁移测试。
2. 验证新版数据被上一稳定版读取时的表现。
3. 不兼容时提供明确错误和导出路径，不能静默清空。
4. 将 schema 变更与 UI/内容发布分成不同部署，降低回滚复杂度。
5. Production 切换前记录上一稳定 deployment ID。

紧急回滚后还要验证：

- 首次设置状态。
- 练习进度。
- 收藏与复盘。
- 数据导出。
- 深层路由。
- 安全规则版本。

## 16. 可移植性与备用托管

为避免被单一平台锁定：

- `npm run build` 始终输出标准 `dist/`。
- Vercel专属逻辑只放在 `vercel.json` 和部署文档中。
- 不因当前纯静态需求引入 Vercel Functions 或专属数据库。
- SPA fallback 同时保留平台无关的验收说明。
- 自定义域名由项目所有者控制，不把 `*.vercel.app` 当作永久品牌域名。
- 保存依赖锁文件、发布记录和前一稳定构建的 commit SHA。

如果 Vercel内容政策、国内可用性、价格或商业计划不再适合，可以用相同 `dist/` 迁移到其他静态托管平台；迁移时重点处理 SPA rewrite、安全头和 origin 导致的本地数据隔离。
